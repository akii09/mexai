---
title: Context Layers
description: Reference for the three context layer file formats — context.md, codebase.md, and rules.md.
---

mexai maintains three Markdown files per project in `~/.mexai/projects/<slug>/`.

## Layer 1 — `context.md`

The primary layer. Read and written most frequently.

### Frontmatter

```yaml
---
name: My Project
slug: my-project
domain: api
stack:
  - TypeScript
  - Node.js
status: active
createdAt: "2024-01-15"
updatedAt: "2024-01-20"
---
```

| Field | Type | Required | Description |
|---|---|---|---|
| `name` | string | ✓ | Human-readable project name |
| `slug` | string | ✓ | URL-safe identifier, auto-generated from name |
| `domain` | string | ✓ | Project type: `web-app`, `api`, `cli-tool`, `library`, etc. |
| `stack` | string[] | ✓ | Technology stack |
| `status` | string | ✓ | `active`, `archived`, or `on-hold` |
| `createdAt` | ISO date | ✓ | Creation date |
| `updatedAt` | ISO date | ✓ | Last update date |

### Sections

```markdown
## Identity

A paragraph describing what this project is, who it's for, and its goals.

## Current State

What is being worked on right now.

## Open Threads

- [ ] Investigate connection pooling performance
- [ ] Review auth middleware for edge cases
- [x] Set up CI pipeline

## Decisions

### Decision title
**Date:** 2024-01-15
**Rationale:** Why this decision was made.
```

### Frontmatter repair

If frontmatter has missing or invalid fields, `mexai doctor --apply` repairs them with safe defaults. `parseContext` also auto-repairs silently instead of throwing.

## Layer 2 — `codebase.md`

The codebase map. Generated by `mexai map`, refined manually.

```markdown
# Codebase Map

## Key Files

| File | Purpose |
|---|---|
| `src/index.ts` | Application entrypoint |
| `src/routes/auth.ts` | Authentication routes |

## Conventions

- All exports are named (no default exports)
- Async/await throughout, no callbacks
- Zod for all external input validation

## Structure

src/
├── routes/         ← HTTP handlers
├── services/       ← Business logic
├── models/         ← Database models
└── utils/          ← Shared utilities

## Patterns

### Service layer pattern
All business logic lives in services. Routes call services; services don't call routes.

## Do Not Touch

- `src/generated/` — auto-generated files, overwritten on build
- `prisma/migrations/` — never edit manually
```

## Layer 3 — `rules.md`

Agent behaviour rules. Written in plain Markdown, no frontmatter.

```markdown
# Agent Rules

## Code Quality

- Follow existing code style — match the patterns already in the codebase
- Write tests for all new functionality
- Keep functions small and focused

## Security

- Never log secrets, tokens, or sensitive user data
- Validate all external input before use
- No eval, no dynamic require

## Review Gates

- All tests pass before suggesting a commit
- No new lint warnings
- No TypeScript errors
```

Rules are never truncated by the token budget. If rules exceed the budget ceiling, a warning is logged.

---

## File locations

All files live at:

```
~/.mexai/projects/<slug>/
├── context.md
├── codebase.md
├── rules.md
├── pending-diff.json    ← temporary, cleared after commit
└── .git/
```

Never edit these files directly — use `mexai edit` or the proper CLI commands. This ensures proper validation and git commits.
